# MACD v3 — Histogram 교차 + SL·TP

기존 v2의 진입·반대 교차 종료·전환·SL을 유지하고 TP만 추가했다.
포지션 종료를 TP/SL만으로 제한한 전략은 아니다. 손절 후 재진입 제한도 추가하지 않았다.
v1과 v2 파일·보고서는 보존하며, 기존 backend/src 및 실행 중인 RSI 배치는 변경하지 않는다.

이번 일괄 실행에서 개발용 Excel 출력기의 행 제한 검사를 선형 시간으로 개선했다.
공통 출력기는 행마다 max_row를 조회해 전체 셀을 반복 탐색했으므로, 같은 제한을 행 번호로 검사하도록 바꿨다.
기존 백엔드에 영향을 주지 않도록 보고서 조정 코드와 Excel 출력기를 backend_dev/reporting에 분리했다.
JSON/CSV 도우미는 재사용하고, Excel 값·서식·차트·시트 구조의 동등성을 테스트했다.
거래 계산과 보고서 수치에는 변화가 없다. 이 임시 분리는 배치 종료 후 공통 구조로 통합할 대상이다.

## 실험 조합

SL:TP=1:2로 (2,4), (3,6), …, (10,20)의 9쌍을 생성했다.
각각 현물 1배 9개, 선물 Long/Short 2·3·4·5배별 9개로 총 45개다.
TP는 SL과 교차 조합하지 않고 2% 간격으로 증가한다.
비교 상대는 같은 시장·배율·SL의 v2이며, 다른 입력은 동일하다.

BTC 1h, MACD 12/26/9, 준비 34봉, 초기 자금 1000 USDT, 배분 100%,
슬리피지 5bps, 현물 편도 수수료 0.1%·선물 0.05%를 사용한다.
기간은 2024-01-02 00:00 ~ 2026-11-01 00:00 UTC(종료 제외)다.
선물은 one_way/isolated와 assume_zero 펀딩을 사용하며, 기존 청산·펀딩 근사 한계는 유지한다.

## 실행 (backend_dev에서)

```powershell
# 선물 2배, SL5%·TP10% 단건
python run_backtest.py --config config/macd/v3/future/long_short/BTC_USDT_USDT/1h/2x/macd_v3_btc_future_1h_2x_sl5_tp10.yaml

# 45개 전체 실행 또는 재개
python run_all.py --version v3
```

일괄 실행은 시작 시 가격/펀딩 데이터를 읽고 준비 기간 포함 완전성을 검사한다.
DB에는 쓰지 않고 개별 결과는 reports/macd/v3/ 아래에 저장한다.
마지막 결과 폴더명에는 기간-SL-TP-MACD 파라미터가 표시된다.

```text
reports/batches/macd_v3/
├── summary.csv      # 각 실험 성과와 SL/TP/강제 청산 건수
├── state.json       # 실행 진행 상태
└── 01.stdout.json … # 개별 실행 출력
```

같은 설정·코드·데이터이며 보고서 해시가 온전한 성공 건은 재실행 시 건너뛴다.
실패·중단된 건은 다시 실행한다. 같은 배치를 두 터미널에서 동시에 실행하지 않는다.
모두 다시 실행하려면 --rerun을 붙인다. CSV를 Excel에서 열어두면 갱신이 막힐 수 있으므로 닫아둔다.
MACD 일괄 실행 중에는 backend_dev의 구현 파일이나 YAML, DB 데이터를 변경하지 않는다.

## 체결 정책과 비교

SL·TP는 실제 진입 체결 가격 대비 비율이다. Long은 진입가 아래에 SL, 위에 TP,
Short는 반대로 배치한다. 고정 가격이며 계좌 ROI나 추적 손절 기준이 아니다.

- 시가 갭은 예약된 교차 주문보다 먼저 처리한다.
- 불리한 갭은 청산 경계를 넘으면 청산, SL만 넘으면 시가 손절이다.
- 유리한 갭으로 TP를 넘으면 시가에서 익절한다.
- 시가가 경계 안이고 한 봉에서 TP·SL을 모두 건드리면 순서를 알 수 없어 불리한 종료를 우선한다.
- SL과 청산 경계 중에는 연속 이동을 가정해 가까운 경계를 먼저 처리한다.
- TP만 도달하면 목표 가격에 체결하며 수수료·불리한 슬리피지를 반영한다.

TP는 maker 대기열을 재현하는 지정가 모형이 아니라 가격 트리거 종료 근사다.
고가·저가 사이 실제 순서·점프는 OHLC만으로 알 수 없다.
v2와 동일하게 신호 교차를 재사용하며 재진입 잠금을 두지 않는다.

TP 종료 건수가 0이면 해당 TP가 실제 거래에 개입하지 않은 결과다.
수익률·낙폭·평균 손익·비용과 TP/SL 건수를 함께 비교하며,
이 한 기간에서 가장 높은 행을 선택하는 것만으로 검증이 끝났다고 판단하지 않는다.

## 전체 실행 결과

45개 전부 성공했고 실패는 0개다. 각 보고서의 6개 산출물과 manifest 해시를 검증했다.
사용자가 제공한 v2 실행 출력에서 중복 1건을 제외한 45개를 같은 시장·배율·SL로 짝지었다.
v3 수익률은 v2 대비 32개 개선, 13개 동일이다. 동일한 13개는 TP 종료가 0건이었다.
모든 실험에서 강제 청산 건수는 0이며 손실은 거래 손익과 비용 누적으로 발생했다.
